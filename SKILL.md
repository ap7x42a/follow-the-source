# Follow the Source

Keep the user's originals within reach for the life of the task. A note can tell you where to look. Only inspecting the original counts as a check.

## Establish what governs the work

Open the supplied material. Keep a compact map in task context of each source's location, the part of the job it guides, and any version the user specified. For a long source, locate its structure, exceptions, and relevant worked examples. For a visual, identify the page, panel, or region to inspect. Put these locators in any existing task handoff so the next agent can retrieve the same originals. Use the scope the user gave each source. An example of how to handle disagreement can guide that behavior without making its characters, wording, or formatting obligatory.

## Reopen at the point of use

| When | What to do |
| --- | --- |
| Starting a decision, section, or batch that depends on the material | Retrieve the relevant part of the original again. Read the surrounding qualifications and applicable exceptions. Identify one concrete implication for the work in front of you, then apply it. |
| Working through a long, repetitive stretch | Divide the work into reviewable batches. If the user gives no cadence, use at most five substantive items or edits between reads. Reopen sooner when a new case changes which guidance applies. |
| Receiving a correction, a revised source, or an unexpected result | Reopen the affected material, find which earlier choices depended on it, and repair any affected work. Respect a version the user explicitly pinned. |
| Resuming after a handoff, interruption, or context compaction | Recover the source locations and reopen the relevant originals before acting. Give any delegate the original locators, the scope they govern, and the instruction to use this same loop. |
| Delivering the result | Inspect the actual output alongside the originals again. Check each applicable requirement, exception, and example-derived choice against a specific part of the output. Fix mismatches and recheck the affected parts. |

One fresh read can cover several decisions in the same batch when they rely on the same passage. For a file or URL, use a fresh read of its contents. For an original message still visible in context, revisit its exact wording. For a screenshot, inspect the image itself. Search hits, filenames, prior quotes in notes, and another agent's assurance only help locate the source.

## Apply what the example demonstrates

Look for the move the example makes in a comparable situation. For instance, if a ticket example records a failed test before escalating, check whether the current case has that evidence. Preserve the sequence if it applies. Supply the current ticket's facts. If several examples point to different actions, look for the condition that explains the difference. Treat a pattern inferred from examples as a working interpretation. Reserve claims of a mandatory rule for something the user or source actually requires.

Use the user's latest direction to resolve scope. If two originals still conflict on a consequential decision, identify the exact passages and ask only about that choice. If an original is inaccessible, retry its locator, tell the user what could not be checked, and carry on with independent work. Ask for the missing source or excerpt if needed. Claim a check only for material actually inspected.

Keep routine checks out of the deliverable. If the user wants an audit, give a short locator, the specific choice it governed, and where that choice appears in the result. A useful entry reads like “Runbook, Escalation criteria → recorded the failed local print test before escalation → ticket 17, diagnostics field.”
